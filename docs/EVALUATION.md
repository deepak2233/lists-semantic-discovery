# Evaluation design

## Three different claims

1. **Software correctness:** Tests verify contracts, security boundaries and failure behavior. They do not prove that users like the recommendations.
2. **Authored regression:** Eight contexts and 44 authored technical-resource descriptions exercise ranking deterministically. Their labels and phrasing were created together, so the scores are optimistic and unsuitable as general quality claims.
3. **Independent relevance:** A future held-out study must establish useful web recommendation quality using actual provider candidate pools. That study is a release gate.

## Included regression

Run `uv run python scripts/evaluate.py`. Results are written to `evaluation/results.json`. For the optional real model, run `uv run --no-sync python scripts/evaluate.py --model-path models/minilm --output evaluation/results_semantic.json`.

Each fixture labels corpus documents from 1 (related) to 3 (highly relevant); unspecified documents are treated as zero. All 44 fixtures enter the ranker. Demo insertion order is excluded from fusion. The corpus digest and optional model revision are recorded. This evaluates ranking over a known small pool, **not candidate discovery or real-web Recall@40**.

Reported metrics:

- NDCG@10: graded ranking quality using gain `2^grade - 1` and logarithmic discount. Ideal ranking includes all judged relevant documents before truncation.
- Recall@10: returned labeled relevant documents divided by all labeled relevant documents for that fixture.
- Precision@5: labeled relevant results in the first five divided by five, including any missing slots as misses.
- Unique exact hosts@10: basic diversity, not a guarantee of independent publishers.
- Local ranker latency: excludes provider calls, extraction and HTTP.

The result files are generated by the scripts, not handwritten success claims. A meaningful comparison should inspect failures as well as averages. MiniLM can lower a fixture score if a small synthetic set favors exact lexical terms. That is useful evidence against blindly enabling a model.

## Proposed independent study

Collect at least 300-500 public article contexts with informed participant consent or a properly licensed test collection. Cover technical and general topics, rare entities, long articles, poor markup, synonym-only relevance, near duplicates, multilingual pages that should be declined, sensitive-page exclusions and empty search results.

Split by source article and topic to limit leakage. Keep a frozen holdout. Build a pooled candidate set from provider-only, lexical and dense variants. Obtain two independent relevance judgments on overlapping samples; resolve disagreements and record agreement. Judge page usefulness rather than simply matching a snippet keyword.

Compare provider-only, BM25-only, dense-only, RRF and RRF plus diversity. Tune dense thresholds and MMR weights on development data only. Report per-slice quality, NDCG@10, useful-result rate, duplicates, domain concentration and returned-result count. Use paired bootstrap intervals for model differences. Do not interpret an uncalibrated cosine as relevance probability.

If click feedback is later introduced, obtain explicit product/privacy approval and prefer minimal aggregated measurements. CTR alone favors sensational titles and position bias. Combine it with opt-in usefulness ratings and quality guardrails; do not quietly start collecting browsing history.

## Performance methodology

Record CPU model, allocated cores, memory limit, runtime/model versions, warmup, cache state, provider plan, concurrency, traffic distribution and failure ratio. Measure cold starts separately. Load tests must include failures and rejected requests, not only successful cached responses.

Use a real HTTPS staging endpoint and actual provider to validate the live p95 target. First test the local API and model in isolation, then provider latency, then the browser flow. Keep the source inputs synthetic/public and redact telemetry. The included local probe establishes only that the measured local configuration handled that specific small workload.

# Deployment and operations

## Development

```bash
uv sync --frozen --extra dev
uv run --no-sync uvicorn lists_api.main:app --host 127.0.0.1 --port 8000 --no-access-log --no-proxy-headers
```

`Settings.from_env()` reads process environment. Python does not automatically load `.env`. Docker Compose does use the supplied `.env` file. Never source an untrusted environment file as a shell script.

## Configuration

| Variable | Default | Purpose |
| --- | --- | --- |
| LISTS_ENV | development | Production enables fail-closed identity/provider/origin checks |
| LISTS_PROVIDER | demo | `demo` authored corpus or `brave` live web search |
| BRAVE_API_KEY | empty | Server-only provider credential; required in live mode |
| LISTS_AUTH_MODE | none | `none` for loopback development; `jwt` for protected API |
| JWT_ISSUER | empty | Trusted HTTPS issuer |
| JWT_AUDIENCE | empty | API audience, not merely the extension client ID |
| JWT_JWKS_URL | empty | Fixed trusted HTTPS signing-key endpoint |
| JWT_REQUIRED_SCOPE | recommend:read | Required space-delimited access-token scope |
| LISTS_ALLOWED_ORIGINS | empty | Comma-separated exact chrome-extension origins in production |
| LISTS_ALLOWED_HOSTS | 127.0.0.1,localhost,testserver | Trusted API Host headers; replace with deployment hosts |
| LISTS_MODEL_PATH | empty | Local reviewed MiniLM artifact directory |
| PROVIDER_TIMEOUT_SECONDS | 3 | Total provider deadline, valid range 0.1-10 |
| CACHE_TTL_SECONDS | 0 | Opt-in result cache, valid range 0-300 |
| REQUESTS_PER_MINUTE | 30 | Per-subject quota per process |
| MAX_INFLIGHT | 8 | Per-process recommendation admission slots, range 1-64 |

Allowlisted origins must be exact IDs: `chrome-extension://` followed by 32 letters a-p. Development accepts unpacked extension origins; ordinary webpage origins are rejected. CORS is a browser control, not an authentication replacement. Non-browser clients can omit Origin and must still authenticate in production.

## Protected staging

1. Provision TLS termination and a controlled hostname. Add gateway request-body read timeouts, total request deadlines and global/account quotas. Restrict backend ingress to that gateway.
2. Register the API audience and `recommend:read` scope at your identity provider. Configure issuer/JWKS locations from a trusted deployment source. Test key rotation and JWKS outage behavior.
3. Supply a provider key through your platform's secret mechanism. Confirm that provider rate limits permit two search calls per accepted recommendation.
4. Configure `LISTS_ENV=production`, `LISTS_PROVIDER=brave`, `LISTS_AUTH_MODE=jwt`, exact extension origins and appropriate hosts. Startup rejects missing settings. Production disables interactive API docs.
5. Start one process initially. The code's limiter, cache, breaker and semaphore are process-local. Multiple Uvicorn workers multiply their limits and memory. Add centralized quotas before horizontal scaling.
6. In the extension settings, grant the specific HTTPS backend host and enter a short-lived developer access token. This supports a controlled technical pilot. Implement managed authorization-code + PKCE sign-in before a public release.

The API supports RS256 access tokens with issuer, audience, exp, iat, sub and scope checks. Do not paste the search-provider secret into the extension. Token expiry is enforced by the server; the client surfaces 401 rather than attempting to keep an expired session alive.

## Semantic setup and container

```bash
uv sync --frozen --extra dev --extra semantic
uv run --no-sync python scripts/download_model.py
docker build --build-arg WITH_SEMANTIC=true -t lists-discovery:local .
docker run --rm --env-file .env -e LISTS_MODEL_PATH=/models/minilm -p 127.0.0.1:8000:8000 -v "$PWD/models/minilm:/models/minilm:ro" lists-discovery:local
```

On Windows, use the equivalent absolute bind-mount path for Docker Desktop. The build installs the optional ONNX runtime; model files are mounted separately and checked at startup. Model artifacts stay outside Git. Include the publisher's license and attribution when distributing a model-containing image.

The default Compose setup is lexical, not semantic. Its 512 MiB limit is an initial development guardrail. Measure RSS and headroom before choosing limits for semantic replicas. Pin a reviewed base-image digest in your production registry after building and scanning it.

## Health, telemetry and targets

- `/health/live`: process responds; deliberately does not require an external provider call.
- `/health/ready`: startup/model initialization completed. It does not assert that the remote provider currently has quota.
- `/metrics`: simple status counters. Protected with the same JWT requirements in protected deployments.
- `X-Request-ID`: fresh correlation value generated by the API. Do not use a page URL as a trace identifier.

Before pilot launch, add latency histograms, upstream status/latency metrics, global quota and spend usage, model memory and admission rejection metrics. Application timing is returned per request but is not yet aggregated into server histograms.

Proposed targets: 99.5% monthly eligible-request availability and p95 live HTTP latency under five seconds at an agreed load. Eligible requests exclude invalid inputs, authentication failures and intentional per-user quota denials; provider failures and overload 503s count as failures. A 99.5% target corresponds to about 216 minutes of unavailability in a 30-day month. Targets require live measurement.

Suggested alerts after telemetry exists: sustained eligible-error ratio above budget, elevated provider 429s, provider deadline failures, admission saturation and spend above a daily budget. Tune thresholds from pilot traffic; this repository does not claim an installed alerting stack.

## Incident runbooks

| Symptom | Checks | Action |
| --- | --- | --- |
| 401 responses | Issuer/audience/scope, clock skew, token expiry, signing keys | Fix identity configuration or renew the user's token; never disable auth |
| Provider 429 or 503 | Subscription quota, upstream health, call counts | Reduce admission/global rate; wait for cooldown; do not create retry storms |
| Latency spikes | Provider deadlines, model CPU/RSS, active requests | Shed load; scale only within provider budget; compare lexical and semantic paths |
| Empty results | Input language, topic quality, provider coverage, filters | Report honestly; inspect synthetic reproductions without logging real page content |
| Startup fails | Missing settings, model manifest/checksum, dependency versions | Restore reviewed config/artifacts; do not silently ignore a configured model failure |
| Possible data exposure | Logging/tracing settings, affected destinations/time window | Stop affected collection, rotate exposed credentials and follow the organization's incident process |

## Rollback

Keep an immutable last-known-good image, model manifest and configuration version. Roll back all three consistently. Remove a faulty extension release using the distribution channel's normal rollback/version process. Avoid changing both the model and the provider-query policy during an incident. Validate health, auth and an authored smoke request after rollback.

There is no database migration in the baseline. If a future owned index is deployed, publish versioned indexes behind an alias and retain the previous validated index for rollback, subject to deletion/retention obligations.

## Validation commands

```bash
uv run --no-sync pytest
npm test
uv run --no-sync ruff check .
uv run --no-sync ruff format --check .
uv run --no-sync python scripts/evaluate.py
uv run --no-sync python scripts/smoke.py
uv export --frozen --no-dev --no-emit-project --no-hashes --output-file /tmp/lists-production-requirements.txt
uv run --no-sync pip-audit -r /tmp/lists-production-requirements.txt
```

`scripts/load_probe.py` only targets the local loopback service. Its default 20 requests fit the default development quota. Larger probes require a deliberate local quota increase and a restarted development service. A loopback result excludes external search, TLS, browser extraction and internet latency.
